GCS Presentation Runbook (Manual Demo Guide)
=============================================

Audience: evaluator / lecturer
Goal: run the simulation manually and collect proof for all GCS requirements.
OS: Windows PowerShell
Project root:
  C:\Users\User\Documents\APU\RTS\Assignment\Satellite_Sim\satellite-gcs-rts


------------------------------------------------------------
0) One-time prep before presentation
------------------------------------------------------------

Open PowerShell and go to project root:

  cd "C:\Users\User\Documents\APU\RTS\Assignment\Satellite_Sim\satellite-gcs-rts"

Build once in release so runtime start is faster:

  cargo build --release

Optional: clear old logs so your demo evidence is clean:

  Remove-Item .\ground.log -ErrorAction SilentlyContinue
  Remove-Item .\satellite.log -ErrorAction SilentlyContinue
  Remove-Item .\gcs_final_report.txt -ErrorAction SilentlyContinue


------------------------------------------------------------
1) Live demo flow (3 terminals)
------------------------------------------------------------

Use 3 terminals:
  - Terminal A: GCS
  - Terminal B: Satellite run #1
  - Terminal C: Satellite run #2 (reconnect proof)

1.1 Terminal A (start GCS first)

  cd "C:\Users\User\Documents\APU\RTS\Assignment\Satellite_Sim\satellite-gcs-rts"
  cargo run -p ground --release -- --duration-s 90

You should see GCS dashboard and it listens on TCP port 8888.


1.2 Terminal B (start first satellite session)

  cd "C:\Users\User\Documents\APU\RTS\Assignment\Satellite_Sim\satellite-gcs-rts"
  cargo run -p satellite --release -- --duration-s 25

Let it run to completion and stop.


1.3 Terminal C (start second satellite session for reconnect proof)

Start this after Terminal B ends (or a few seconds later):

  cd "C:\Users\User\Documents\APU\RTS\Assignment\Satellite_Sim\satellite-gcs-rts"
  cargo run -p satellite --release -- --duration-s 25

This proves GCS reconnect behavior after disconnect.


1.4 End run

Wait until Terminal A (GCS) finishes by timer.
After it exits, final files are generated:
  - ground.log
  - satellite.log
  - gcs_final_report.txt


------------------------------------------------------------
2) Fast evidence extraction commands
------------------------------------------------------------

Run these in project root after demo:

2.1 Connection / reconnect / real TCP

  rg "Satellite connected from|telemetry_rx stopped|session tasks cleaned up|GCS listening" .\ground.log
  rg "Connected to Ground Control Station|uplink_rx: received cmd|command executed cmd" .\satellite.log

2.2 Performance report snapshots + final summary

  rg "=== PERFORMANCE REPORT ===|=== GCS SIMULATION COMPLETE ===" .\ground.log
  rg "=== SATELLITE SIMULATION COMPLETE ===" .\satellite.log
  Get-Content .\gcs_final_report.txt

2.3 Fault/interlock/rejections/alerts

  rg "fault received|interlock APPLIED|interlock CLEARED|COMMAND REJECTED|CRITICAL GROUND ALERT" .\ground.log

2.4 Telemetry decode/latency/drift/re-request/loss-contact

  rg "telemetry_rx sensor=|decode_us=|latency_us=|drift_us=|PACKET LOSS DETECTED|DELAYED PACKET DETECTED|RequestTelemetry enqueued|LOSS OF CONTACT" .\ground.log

2.5 Uplink deadline and jitter/backlog/drift/system load

  rg "DISPATCH DEADLINE MISSED|uplink_tx: sent|uplink_jitter_p99_us|telemetry_backlog_max|task_drift_uplink_last_us|task_drift_telemetry_last_us|system_load_pct" .\ground.log


------------------------------------------------------------
3) Requirement-by-requirement proof checklist
------------------------------------------------------------

IMPORTANT:
- Prefer runtime proof from logs and final report.
- If a specific event does not naturally happen in that run, use source-code proof commands in section 4.


=== Ground Control Station (GCS) ===

1) Telemetry Reception and Decoding
-----------------------------------
[A] Receive telemetry via sockets, decode within 3ms
  Runtime proof:
    - ground.log lines with "telemetry_rx sensor=..." and "decode_us="
    - no "DECODE DEADLINE MISSED" during healthy run
  Commands:
    rg "telemetry_rx sensor=|decode_us=|DECODE DEADLINE MISSED" .\ground.log

[B] Log packet reception latency and drift
  Runtime proof:
    - "latency_us=" and "drift_us=" in telemetry_rx logs
  Commands:
    rg "telemetry_rx sensor=.*latency_us=.*drift_us=" .\ground.log

[C] Trigger re-requests on missing/delayed packets
  Runtime proof:
    - "PACKET LOSS DETECTED — enqueuing RequestTelemetry"
    - "DELAYED PACKET DETECTED — enqueuing RequestTelemetry"
    - "telemetry_rx: RequestTelemetry enqueued"
  Commands:
    rg "PACKET LOSS DETECTED|DELAYED PACKET DETECTED|RequestTelemetry enqueued" .\ground.log

[D] Simulate loss of contact if >=3 packet fails in sequence
  Runtime proof (if triggered):
    - "SATELLITE LOSS OF CONTACT: 3+ ..."
    - contact_status transitions to LOST in UI/logs
  Commands:
    rg "LOSS OF CONTACT|SATELLITE LOSS OF CONTACT" .\ground.log


2) Command Uplink Scheduler
---------------------------
[A] Maintain real-time command schedule
  Runtime proof:
    - repeated "uplink_tx: sent" lines over run
  Commands:
    rg "uplink_tx: sent" .\ground.log

[B] Enforce urgent deadlines <=2ms dispatch
  Runtime proof:
    - "dispatch_us=" in uplink_tx lines, and deadline miss logs if violated
  Commands:
    rg "uplink_tx: sent|DISPATCH DEADLINE MISSED" .\ground.log
  Final report fields:
    - cmd_deadline_misses

[C] Validate commands with safety interlocks
  Runtime proof:
    - "COMMAND REJECTED ... reason=interlock_active"
  Commands:
    rg "COMMAND REJECTED|interlock_active" .\ground.log

[D] Log deadline adherence and rejection reasons
  Runtime proof:
    - "DISPATCH DEADLINE MISSED"
    - "COMMAND REJECTED"
  Final report fields:
    - cmd_deadline_misses
    - cmd_rejected_count
    - cmd_rejection_last_reason


3) Fault Management and Interlocks
----------------------------------
[A] Simulate reception of fault messages
  Runtime proof:
    - "fault_mgr: fault received"
  Commands:
    rg "fault received" .\ground.log

[B] Block unsafe commands until resolved
  Runtime proof:
    - interlock active then rejection lines during that period
  Commands:
    rg "interlock APPLIED|COMMAND REJECTED|interlock CLEARED" .\ground.log

[C] Track interlock latency
  Runtime proof:
    - "interlock_latency_us="
  Commands:
    rg "interlock_latency_us|interlock APPLIED" .\ground.log
  Final report fields:
    - interlock_max_us

[D] Document and explain all command rejections
  Runtime + report proof:
    - log rejection lines
    - final report reason field

[E] Trigger critical alert if >100ms
  Runtime proof if triggered:
    - "CRITICAL GROUND ALERT: interlock exceeded 100ms"
  Commands:
    rg "CRITICAL GROUND ALERT" .\ground.log
  If not triggered in that run:
    - show code evidence in section 4 proving threshold check is implemented.


4) System Performance Monitoring
--------------------------------
[A] Benchmark uplink jitter, telemetry backlog, task execution drift
  Runtime proof:
    - PERFORMANCE REPORT includes:
      uplink_jitter_p99_us
      telemetry_backlog_max
      task_drift_uplink_last_us
      task_drift_telemetry_last_us
  Commands:
    rg "uplink_jitter_p99_us|telemetry_backlog_max|task_drift_uplink_last_us|task_drift_telemetry_last_us|=== PERFORMANCE REPORT ===" .\ground.log

[B] Record missed deadlines, system load, fault recovery metrics
  Runtime proof:
    - cmd_deadline_misses in performance/final logs
    - system_load_pct
    - interlock/fault timing logs
  Commands:
    rg "cmd_deadline_misses|system_load_pct|fault received|interlock APPLIED|interlock CLEARED" .\ground.log

[C] All real-time actions logged with timestamps
  Runtime proof:
    - all log lines contain timestamps
  Commands:
    rg "^\d{4}-\d{2}-\d{2}T" .\ground.log


=== Shared System Requirements ===
